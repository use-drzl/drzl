Test-only. Adds the nullable path and a key-presence axis to both differential parity passes, and
changes no source: `git diff master..HEAD -- 'packages/*/src'` is empty.

Nothing in the parity comparison was nullable before this: 0 of 40 Postgres columns, 0 of 29 MySQL
and 0 of 14 SQLite. Every generator emits a different shape for a nullable column, and that shape is
what most real schemas actually use, so the path most consumers depend on was generated by every run
and compared by nothing.

The comparison also could not see key optionality at all, because the harness read `s.properties[k]`
and TypeBox's `Optional` modifier is inert on an extracted property. A TypeBox generator that got
optionality wrong in either direction passed both passes.

Two defects the new coverage found are filed rather than fixed, since neither has red-then-green
evidence yet: a nullable column the analyzer cannot name emits a schema whose key TypeBox lets go
missing, so a row that never mentions the column validates; and official's TypeBox `uuid` schema
accepts nothing without a `FormatRegistry`, which makes that pairing unreadable rather than green.
